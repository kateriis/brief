# Бриф на розробку сайту

Покрокова анкета для клієнтів: 10 етапів по 3–5 питань. Чиста статика (HTML + CSS + JS), без фреймворків і збирачів.

| Файл | Що в ньому |
|---|---|
| `index.html` | розмітка |
| `styles.css` | оформлення |
| `app.js` | логіка; **питання — масив `STAGES` на початку файлу**, далі `OWNER` (фото, Telegram, документи) |
| `config.js` | лише адреса приймача (Cloudflare Worker) |
| `worker.js` | код для Cloudflare — на сайт його завантажувати не обов'язково |
| `assets/photo.jpg` | ваше фото: на вступі — чорно-біле тісне кадрування, у фіналі — кольорове |
| `assets/logo.svg` | логотип «КК» у шапці й підвалі |

---

## 1. Публікація на GitHub Pages

1. Створіть репозиторій на GitHub і завантажте в нього всі файли з цієї папки.
2. **Settings → Pages → Build and deployment → Source: Deploy from a branch**, гілка `main`, папка `/ (root)` → **Save**.
3. За хвилину сайт буде за адресою `https://ваш-логін.github.io/назва-репозиторію/`.

Поки `config.js` порожній, анкета працює повністю, але замість надсилання пропонує клієнту **завантажити файл з відповідями** і написати вам у Telegram. Відповіді не губляться.

## 2. Бот у Telegram

1. Напишіть [@BotFather](https://t.me/BotFather) → `/newbot` → придумайте ім'я. Збережіть **токен** (вигляд `123456:ABC…`). Нікому його не показуйте.
2. Знайдіть свого бота в Telegram і натисніть **Start** — інакше бот не зможе вам писати.
3. Дізнайтеся свій **CHAT_ID**: відкрийте в браузері
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates`
   і знайдіть `"chat":{"id": 123456789`. Це число і є CHAT_ID.
   *Для групи:* додайте бота в групу, напишіть у ній будь-що і відкрийте те саме посилання — id групи починається з `-`.

## 3. Cloudflare Worker (проміжний сервіс)

1. Зареєструйтеся на [dash.cloudflare.com](https://dash.cloudflare.com) (безкоштовного тарифу достатньо).
2. **Workers & Pages → Create → Create Worker** → назвіть, наприклад, `brief` → **Deploy**.
3. **Edit code** → видаліть усе й вставте вміст `worker.js` → **Deploy**.
4. **Settings → Variables and Secrets → Add**:
   - `BOT_TOKEN` — токен бота, тип **Secret**;
   - `CHAT_ID` — число з кроку 2.3;
   - `ALLOWED_ORIGINS` — адреса вашого сайту **без шляху**, наприклад `https://ваш-логін.github.io`. Тоді інші сайти не зможуть слати вам спам через ваш Worker.
5. Скопіюйте адресу Worker (вигляд `https://brief.ваш-логін.workers.dev`) і вставте її в `config.js`:

```js
window.BRIEF_CONFIG = {
  endpoint: 'https://brief.ваш-логін.workers.dev'
};
```

6. Завантажте оновлений `config.js` на GitHub. Готово — заповніть анкету самі й перевірте, що прийшло.

**Як приходять відповіді.** Спершу зведення (ім'я, контакт, компанія, головна дія, продукт, тип сайту, дедлайн, бюджет), далі кожен етап окремим повідомленням: питання жирним, під ним відповідь. Порожні питання не показуються. Довгі відповіді діляться за абзацами, щоб не перевищити ліміт Telegram у 4096 символів. Файли приходять окремими документами з підписом «Файл до брифу #id».

**Якщо щось не дійшло**, клієнт бачить вікно «Не вдалося надіслати» з кнопками «Спробувати ще раз» і «Завантажити відповіді». Чернетка при цьому лишається в браузері.

## Як змінювати питання

Відкрийте `app.js`, масив `STAGES`. Кожен етап:

```js
{
  id: 'client',                 // латиницею, без пробілів
  title: 'Клієнт',              // назва етапу
  desc: 'Опис під назвою',
  questions: [ … ]
}
```

Кожне питання:

```js
{
  id: 'audience',               // унікальний, латиницею
  label: 'Хто зазвичай у вас купує?',
  hint: 'Підказка під питанням',          // необов'язково
  required: true,               // обов'язкове
  key: true,                    // плашка «важливо»
  type: 'long',                 // short | long | radio | checkbox | files | links
  options: ['Так', 'Ні'],       // для radio / checkbox
  other: true,                  // додати варіант «Інше» з полем
  summary: 'Аудиторія'          // показати в першому повідомленні з цією назвою
}
```

- Щоб додати питання — скопіюйте сусіднє і змініть `id` та текст.
- Щоб прибрати — видаліть об'єкт разом з комою.
- Щоб перенести на інший етап — переставте об'єкт у потрібний масив `questions`.
- Тримайте 3–5 питань на етапі, щоб анкета не лякала обсягом.
- Якщо змінили питання, а у вас у браузері лишилась стара чернетка, — змініть `DRAFT_KEY` в `app.js` (наприклад, на `…-v2`).

## Ваші дані

У `app.js` об'єкт `OWNER`:

- `name`, `telegram` — ім'я в шапці й підвалі, кнопка «Написати в Telegram»;
- `role` — підпис під фото на вступі;
- `photo` — шлях до фото (`assets/photo.jpg`); поки файлу немає, на вступі фото ховається, а у фіналі показуються ініціали на бордовому тлі;
- `replyTime` — термін відповіді на фінальному екрані;
- `legal` — документи: впишіть посилання в `url`. Перші два документи також підставляються в чекбокс згоди.
- `contacts` — посилання в підвалі (Instagram, пошта тощо додаються так само, як Telegram).
